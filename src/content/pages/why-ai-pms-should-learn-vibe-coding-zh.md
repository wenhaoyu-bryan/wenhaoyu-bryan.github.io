## 产品经理的瓶颈正在变化

传统流程中，产品经理通常等待工程团队构建后再评审。借助 Vibe Coding，产品经理可以更快把一些想法变成可测试的原型。挑战不仅是提出想法，还包括把想法变成可验证的东西。

## 产品经理的 Vibe Coding 是什么？

Vibe Coding 是通过自然语言与 Claude Code、Cursor 等基于大模型的工具协作，构建可运行原型。你定义产品意图、架构约束与设计边界，模型协助生成代码。

对于产品经理，我关注的是三种能力：

1. **更快验证。** 在投入工程资源之前，测试产品想法是否合理。
2. **更具体的需求。** 亲手制作原型后，PRD 可以更具体，也更贴近技术实现。
3. **更紧密地与工程团队协作。** 除了用户故事，也可以围绕架构和数据流交流。

## 我的体会

通过 Vibe Coding 构建 [Prompt-to-Ontology](/zh/projects/prompt-to-ontology/) 的经历让我认识到，产品经理最有价值的产出不一定是代码，而是清楚定义架构边界、说明数据流，以及明确什么才算完成。

模型可以协助实现，产品经理负责产品判断；两者都需要审查和迭代。

## 如何开始

不需要先成为软件工程师，但可以练习：

- 定义清晰的架构约束。
- 描述数据模型和 API 契约。
- 用技术上可理解的方式描述用户流程。
- 从产品正确性的角度检查生成的代码。

从一个范围清楚的小原型开始，通过实际验证不断学习。
